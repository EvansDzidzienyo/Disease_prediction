# Agricultural Disease Presence Prediction

An experimental machine-learning project using an agricultural dataset to classify the recorded `Disease_Presence` target. The Streamlit interface is a demonstration of the training pipeline, not a field diagnosis or agronomic recommendation.

## Dataset and target

The committed `classification_data.csv` contains 2,200 rows and these columns: `Date`, `Region`, `Crop_Type`, `Rainfall_mm`, `Temperature_C`, `Soil_Moisture`, `Fertilizer_Used`, `Pest_Presence` and `Disease_Presence`.

There are 2,193 rows with a recorded target and 7 rows with a missing `Disease_Presence` value. Among the labeled rows, the target values are 0 (539 rows) and 1 (1,654 rows). The notebook and dataset do not provide independently verified documentation defining the semantic meaning of each numeric class. Accordingly, the app displays the raw predicted class and does not label 0 or 1 as confirmed disease absence or presence.

**Important distinction:** `Disease_Presence` is the model target. `Pest_Presence` is an input feature, not the target.

The original notebook extracts day-of-month from `Date`, uses the remaining variables as predictors, and applies imputation, scaling, one-hot encoding, SMOTE and Logistic Regression. The reproducible training script below preserves the target and feature intent, but uses a scikit-learn Pipeline with training-only preprocessing and Logistic Regression with balanced class weights. This avoids applying ordinary SMOTE to one-hot encoded categorical columns, where synthetic interpolation can create fractional category indicators.

The dataset includes missing values in several predictor columns. The new pipeline imputes numeric values using the training-set median and categorical values using the training-set most frequent category. The 7 rows with missing target values are excluded from supervised training and evaluation.

The repository does not establish the dataset's original source, collection protocol, geographic sampling design, crop coverage or consent/data governance. The presence of Ghanaian region names in the data is not sufficient evidence of representative field data.

## Reproduce the model

The automated workflow uses Python 3.12. From the repository root:

```bash
python -m venv .venv
# Windows
.venv\\Scripts\\activate
# macOS/Linux
source .venv/bin/activate

python -m pip install --upgrade pip
pip install -r requirements.txt
python train.py
pytest -q
```

Training creates:

- `artifacts/disease_presence_pipeline.joblib`: the complete preprocessing and classifier pipeline.
- `artifacts/metrics.json`: held-out test metrics, class-wise report and confusion matrix.

Launch the Streamlit interface after training:

```bash
streamlit run stream.py
```

The app loads the same pipeline produced by `train.py`; it does not separately recreate preprocessing. The original `pest_model.joblib` is retained as historical project material, but the updated app uses the new artifact.

## Evaluation

The reproducible evaluation uses a stratified 80/20 train/test split with `random_state=42`. Preprocessing is fitted only on the training partition. The model is Logistic Regression with `class_weight="balanced"`. Exact accuracy, macro/weighted F1, class-wise precision/recall/F1 and confusion matrix are generated by `python train.py` and written to `artifacts/metrics.json`.

No performance figure is claimed in this README until the automated training and test workflow has completed successfully. A successful workflow verifies repeatable training, prediction, serialization/reloading and inference with a missing numeric input and an unseen categorical value; it does not establish real-world agronomic validity.

## Limitations and responsible use

- This is a learning and demonstration project, not a substitute for field inspection or advice from qualified agricultural extension professionals.
- Do not use model output alone to make crop treatment, pesticide, fertilizer or other farm-management decisions.
- The meaning of target values 0 and 1 is not independently documented in the repository and must be confirmed from the dataset creator before interpreting predictions.
- Dataset provenance, collection method, geographic coverage, crop coverage and representativeness are not established.
- Performance on this dataset does not establish generalisation to other farms, regions, seasons or crop varieties.
- Further validation against independently collected field observations and review by agronomy experts would be required before any practical use.
